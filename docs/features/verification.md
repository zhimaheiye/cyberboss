# 信息监控核验与重试

## 行为

- watch 作业结束时必须提交核验状态、结论、来源；发生查询失败后还要说明替代渠道的恢复依据。缺失报告、缺失来源、结果不确定或未解决失败，均记录为 `incomplete`，不能显示“静默完成”。
- Agent 在失败后自行切换关键词、来源、直读页面、HTTP 或浏览器，使用 `cb_verification` 留下方法、目标、结果／错误。最终来源报告属于 Agent 的观察记录，不等于人工确认。
- 启用中的 watch 核验未完成时，进程安排 15、60、180、360 分钟的退避重试，重试间隔上限为 6 小时；原周期保留并可提前触发核查，到期合并为一轮，成功后清除重试。暂停、静默、有效窗口和正在执行的同一作业仍受保护。服务重启保留重试安排，关机期间不会执行。
- 每段连续失败首次进入提醒箱；后续重试保留在执行记录，避免逐次弹出。核验失败通知不会占用业务提醒的冷却时间。部分信息已确认可以提醒，同时对未查清部分继续重试。
- 有副作用的 operation 不套用 watch 自动重试，避免重复提交；人工门槛或结果未知继续按既有阻塞规则处理。
- 手动停止 watch 本轮会清除该轮重试，保留原周期；暂停整个作业则原周期和重试均不执行。

## 执行详情

显示核验结论、失败来源、替代尝试、来源依据和当轮安排的重试时间。作业卡片显示当前重试安排。原始 Codex 会话采用流式读取，只补录对应时间段的工具输入输出，不读取或展示模型私有推理。工具正文中的已知访问失败也会标记失败；执行记录不再仅依赖工具传输状态。

已有历史运行状态不改写。打开旧详情可以补出原始工具正文，但不将旧的完成记录伪装成由新机制审核过。未完成记录不符合正常流水的清理条件。

## 实现与边界

`verification.js` 处理记录与结论门槛，`app.js` 负责调度和通知，`tools.js` 提供记录工具，`run-history.js` / `run-progress.js` 补录与呈现失败；界面位于 `RunProgress.jsx` / `Jobs.jsx`。提示词规定替代查询与来源核验。

该门槛保证缺失证据和已知失败不会直接归为正常静默；来源真实性与检索覆盖仍依赖 Agent 实际核对，不能凭结构化字段宣称所有事实正确。原始工具输出缺失时如实显示缺口。详情遮盖敏感字段并截断长文本，保存在本机数据目录，不提交到公开仓库。

本批按用户要求重新执行实际监控作业；未额外运行自动测试、lint、类型检查或浏览器 UI 验收。实际运行结果另见交接。
