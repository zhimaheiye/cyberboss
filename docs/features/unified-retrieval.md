# 统一检索与工具关联

## 目标与页面组织

用户存放的任务、工具、事件和资料保持各自的管理方式，Agent 可以跨来源查找和联系它们。参考已有任务工坊的任务描述与独立能力条目设计，继续使用当前工作台的任务和时间线数据。

- **待办事项**：沿用 OpenTodo。任务说明可写背景、目标、限制和完成条件，详情增加「相关工具与资料」。已有完成来源与更正时间线继续保留。
- **工具箱**：独立管理软件、网站、脚本、MCP 和方法。可填写能力、适用场景、限制、入口、标签、别名、可用状态，支持编辑和归档。没有对应任务时也能保存。
- **生活时间线**：继续记录事件和来源。现有 Markdown 页面显示为「笔记」，原文件路径与 `cb_memory` 接口兼容。
- **全局搜索**：页头搜索按钮跨来源查找，支持来源筛选、归档筛选、分页和完整原文阅读。原文视图可以建立关联或跳转所属页面。
- **设置**：用户自行配置向量接口和参与向量化的来源。关键词检索始终可用。

工具箱条目只保存描述和入口；执行仍使用本机 Agent 已配置的实际工具与授权。工具条目的“可用”是记录状态，执行时仍需核对当前情况。

## 打开外部笔记

工具箱入口可保存 `obsidian://open?vault=...&file=...`，卡片提供「打开笔记」。对话的 Markdown 链接与裸 URI、待办卡片说明、工具详情及搜索原文也支持点击此协议。URI 参数原样保留，不重复编码。当前支持 open 动作和 vault／file／path／paneType 参数；动作由用户点击后交给系统 Obsidian 协议处理器。

可继续在 Obsidian 管理活跃的每日清单，工作台保存入口及用途并参与关联。打开链接不读取、同步或导入笔记正文；Agent 读取或编辑正文仍需要真实本地路径或已配置的 Obsidian MCP。浏览器可能提示允许打开外部应用。参见 [Obsidian URI 官方说明](https://obsidian.md/help/Extending%2BObsidian/Obsidian%2BURI)。

实现位于 `web/src/LocalLinks.jsx`，统一限制可点击协议。没有添加任意系统命令执行接口。个人仓库名、笔记名和 URI 仅由用户保存在本机数据中。

## 读取的原始内容

| 来源 | 检索内容 |
| --- | --- |
| 待办 | OpenTodo 任务标题、完整描述、完成状态、日期和周期；列表分页、详情分批读取 |
| 工具 | 能力、场景、限制、入口、标签、别名、状态 |
| 托管事项 | 执行说明、通知内容、上下文、计划、状态和阻塞依据 |
| 时间线 | 事件文字、时间、来源与依据类型 |
| 对话与提醒 | 工作台保存的全部消息文字和图片附件名称 |
| 笔记 | 当前数据目录 `memory/*.md` |
| 减少决策 | 当前场景、节点、选项，以及已有导入参考笔记 |
| 执行与经验 | 执行摘要、结果、错误和当前任务技能内容 |
| 任务状态记录 | 完成、更正、确认等事件的操作者、依据和时间 |
| 答案之书 | 本机句库和主动收藏的问题与答案 |
| 呼吸记录 | 已保存的练习时长、模式、结果和反馈 |

读取原记录形成临时检索文档；任务内容不另建持久副本。来源标识、原文摘要、时间与内容哈希随结果返回，可继续分页读取原文。待办详情缓存最多 30 秒，经过工作台的待办变更会立即清除缓存；单条详情不可读取时保留其他结果并显示缺口。

第一版检索范围为表内已接入的记录。图片像素未做 OCR 或多模态向量化；执行记录只索引摘要，不自动纳入原始工具输入／输出；OpenTodo 原生独立笔记、项目说明和评论未纳入统一索引，仍可通过对应 OpenTodo 工具读取。配置文件、凭据和服务令牌不作为检索来源。被删除或变化的内容不会继续用旧向量命中，但历史关联会保留并标记变化。

## Agent 行为与关联

`cb_recall` 提供 `search`、`read`、`status`。提示词要求 Agent 结合需求、能力、场景、别名换词检索，阅读来源后判断用途、限制和实际可用性。关键词命中或向量相似度提供线索，关联理由由 Agent 结合原文说明。

`cb_toolbox` 提供工具增改、检索和关联操作。关联记录引用两个来源的 `ref/hash`，保存依据、提出者、版本及操作历史。Agent 保存的关联标记为建议，用户可确认、忽略或自行建立关联；用户已有决定不会被 Agent 覆盖。原文变化后标记待核对，确认旧建议前需要重新读取。每次修改带版本，避免覆盖页面或 Agent 的并发修改。

关联可用于推进已授权任务，无需先逐条点击确认。人工确认表达用户认可；它不代表工具已执行或任务已完成。执行结果与任务完成归因继续走原有机制。

既有自然唤醒可以围绕当前任务和近期事件查找联系。没有新情况沿用静默规则，不新增独立的检索轮询任务。界面「让 Agent 找有用的联系」将来源带入对话草稿，由用户发送。

## 配置向量模型

在「设置 → 统一检索与向量模型」填写：

1. **接口地址**：OpenAI 兼容 embeddings 接口。可填 `http://127.0.0.1:端口/v1` 或完整 `/embeddings` 地址；服务端仅按需要追加 `/embeddings`。
2. **模型名称**与服务要求的 **API Key**。本机无需鉴权的接口可以留空。更换地址时旧密钥不会带过去，需要重新填写。
3. **向量维度**可留空。只有服务支持指定维度时填写。
4. 选择参与向量化的来源，启用后保存。可先点击「测试已保存的接口」，它只发送固定的“连接测试”文字。
5. 点击「更新索引」。也可开启「搜索时自动更新」，首次搜索和内容变化时后台处理缺失片段。

配置保存本身不发送全文。实际向量化会将所选来源的文字发送给配置的服务，语义查询会发送搜索词；使用本机服务可将此处理留在本机。Codex 订阅登录与此接口分别配置。

接口契约参考 [OpenAI embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create)：`model`、`input`、`encoding_format: float`、可选 `dimensions`，读取 `data[].index/embedding`。兼容服务的具体参数支持需用其实际接口核对。

## 索引与失败处理

- 文字按可配置长度分段并保留少量重叠；内容哈希未变化的片段复用向量。默认每段 1600 字符、每批 8 段。
- 模型、地址、维度或分段长度改变后，旧配置的向量不参与搜索；「全部重新向量化」可手动重建。
- 本机保存归一化向量，搜索用余弦相似度与关键词排名融合；返回片段与原始来源供核对。当前采用内存扫描，面向个人规模的数据，不额外安装向量数据库。
- 每批成功后落盘，页面显示片段进度、更新时间、错误和来源读取缺口。中断后可继续更新，已成功的相同片段复用。
- 手动停止后当前进程不自动重新开始，手动更新或重新保存配置可恢复。请求失败后停止自动索引重试，修正配置或手动更新再继续。
- 单次接口请求最长 45 秒。查询失败保留关键词结果；缺少向量时展示覆盖缺口。来源暂时无法读取时显示提示，不能把部分结果称为完整检索。
- 原内容删除后搜索立即按当前内容过滤；下一次更新索引清除已删除的向量。向量化后的来源和内容是否有效，在查询时再次核对。
- 正常巡检的定期清理直接移除对应向量，不等待下次全文索引；具体保留条件见[巡检保留策略](retention.md)。设置页可展开已保存片段的来源分布。

## 本机数据与实现位置

默认均在项目 `data/desktop/`：

- `toolbox.json`：工具、关联及历史。
- `search/settings.json`：向量接口配置与密钥；只通过本机设置页面维护，返回页面时不回传密钥。
- `search/vectors.json`：向量、来源引用和内容哈希，不存整段原文；向量本身仍是私有派生数据。

这些文件均受现有 `data/` 忽略规则保护，不上传公开源码仓库。密钥当前保存在本机配置文件中，没有额外加密；配置接口和检索工具不返回它。具备本机文件访问权限的进程仍可能读取文件。

后端：`src/desktop/search-sources.js`、`retrieval.js`、`toolbox.js`，接入 `app.js`、`tools.js` 和 `server.js`。前端：`Search.jsx`、`Toolbox.jsx`、`RetrievalSettings.jsx` 及既有待办、笔记、设置页面。Agent 策略：`templates/desktop-instructions.md`。
