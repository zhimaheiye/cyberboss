# 项目备份与公开范围

## 保存方式

代码与通用开发文档通过 Git 提交，并普通推送到个人 `origin/main`。按有实质成果的开发批次保存，切换功能或交接时也保存；不依赖固定时间任务自动上传未审阅的工作区。

2026-11-14 查得当前 origin 为 `https://github.com/zhimaheiye/cyberboss.git`，仓库公开。之后同步前再次核对目标，避免向上游或错误仓库推送。提交不会替代功能验收；根据当前约定，不为存档而主动跑测试、类型检查、lint、构建或浏览器测试。

## 可上传内容

- 通用源码、启动／安装脚本、依赖锁文件、项目自带静态资源。
- 产品说明、功能约定、脱敏的开发记录和维护指南。
- 明确不含真实凭据与个人业务数据的既有测试代码；保存测试文件不代表运行或通过。

## 本机保留内容

`data/` 包含聊天、图片、任务、执行记录、观察、记忆、学习技能、通知订阅、服务令牌、VAPID 密钥及 OpenTodo 数据与凭据。整个目录均不提交。

答案之书的第三方通用句库、个人句子、收藏和原始下载文件同样仅留在 `data/desktop/answer-book/`（或用户配置的数据目录）。公开仓库只保留功能和来源／导入说明。导出的 JSON 也属于用户数据，不加入源码提交。

环境文件、MCP 私有配置、用户登录状态、日志、本机备份及 `docs/private/` 同样排除。凭据也不放入提交说明、PR 正文和公开文档。通用 `example` 文件须使用占位符。

公开之前审阅本批文件清单、差异及凭据／个人路径线索。模式搜索只能帮助发现问题，不能保证识别全部隐私；发现疑似内容先本地保存再脱敏或排除。不要用 `git add -f` 把运行数据塞进源码备份。

## 恢复代码与数据

远程仓库可以重新克隆，按提交查看或恢复代码版本。需要回退时优先在新目录／分支查看，避免覆盖正在使用的数据或尚未提交的修改。

运行数据如需备份，应在工作台与 OpenTodo 停止写入后，完整复制 `data/desktop/` 到用户指定的本机或私有备份位置。不要把包含身份凭据的压缩包上传到当前公开仓库。本轮没有设置运行数据的自动异地备份。
