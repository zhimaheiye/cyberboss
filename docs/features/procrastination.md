# 拖延速查

从侧栏「拖延速查」或首页进入，可以留空事项、写一句话或选择今天和已逾期的待办。首页近期事项与待办卡的「卡住了」会直接带入选中的待办。

## 从卡点到动作

起步模板包括精力有限、任务范围不清楚、方案难推进、重复或被打断、缺少材料或进度信息、多件事争用时间六类。选择方法后会看到具体的行动建议。有更窄的做法时，可点「缩小本次范围」，例如从处理一批条目缩到完整处理一个代表性条目并核对结果。行动建议可以直接编辑。页面提供可选的五分钟倒计时、呼吸引导和笔记草稿。

拆解以真实进展为准。按照用户已有能力和实际目标选择范围，每个子任务应有可以独立完成的结果或明确的完成条件。表达保持平实，首页保持完整。

绑定待办后可把动作追加到说明，保留原日期与时刻。临时事项可加入待办。「交给 Agent 准备」预填托管事项编辑器，初始状态为待接管。「调整待办日期」可选择一项或多项，确认后使用 OpenTodo 的排期操作保留原时刻。反馈只记录这次尝试的结果。

## 使用手边资源

动作先在本机呈现。资源区随后读取固定资源、该待办已确认的关联，并通过本地关键词搜索匹配工具、笔记、对话、托管事项与参考资料。可以改关键词、打开原文，或将资源固定在某个卡点。自动匹配使用关键词模式，即使已配置向量模型，也不调用嵌入服务。

「请 AI 帮我安排」可选择时间、精力和执行者，点击发送才提交材料，包括当前事项、动作、部分相关资源摘要与近期待办标题。Codex 在现有对话中回复。启用了 Magpie 时，也可以向它发送一次纯文本请求并在速查页查看建议。待办写回、托管和改期有各自的操作按钮。

## 改成自己的速查表

- 「编辑速查表」可以添加、停用和调整卡点与方法的顺序，编辑问题和不同范围的行动建议。正在使用的建议可临时改写或另存为常用方法。已保存速查表中仍使用内置方法的条目会读取新版方法文案，原有开关、排序、固定资源和个人方法继续有效。
- 点击「开始动了」「还是卡住」「改期或转交了」才产生反馈。相同卡点内按平滑后的开始比例排序，即（开始次数 + 1）/（开始次数 + 卡住次数 + 2）。相同分数时个人方法优先，其余按编辑顺序。改期或转交单独统计。
- 「我的使用反馈」展示方法计数。工作台统一检索的「拖延速查」来源提供卡点、方法、固定引用和汇总数，Codex 可在用户要求时读取并整理。

## 存放位置

通用起步模板随源码发布。用户修改后的速查表保存在工作台数据目录的 `procrastination/playbook.json`，反馈保存在同目录的 `history.json`。默认数据目录是项目内的 `data/desktop/`。首次读取直接使用通用模板，保存修改时才落盘。编辑检查版本号，反馈用尝试编号去重。
