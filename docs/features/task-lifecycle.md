# 待办、托管作业与完成时间线

更新：2026-11-17。源码已接入；本批未测试、构建、重启或做浏览器验收。

## 已确定行为

- 常规 Agent 循环工作保留在「交给 Agent」。工作台待办、首页待办数量和近期事项默认隐藏关联周期 `watch`／`operation` 的卡片，包括暂停与阻塞状态；隐藏不删除 OpenTodo 原数据。
- 托管编辑器提供自动／保留在待办／只在托管事项显示。确实需要人亲自完成的关联待办可以显式保留；同一待办被多项作业关联时，显式保留优先。
- Agent 默认只创建循环作业定义，不再为每次后台工作建立重复待办。后台异常、人工接手进入提醒箱；正常静默执行只留执行记录。历史阻塞且有错误依据的作业在新版本启动时补提醒，同一错误记录去重。
- 异常提醒不再因关联作业非 active 被推送层或页面投递层过滤；呼吸练习和免打扰规则仍生效。实际推送送达尚未验收。

## 完成判断与核查

Agent 可以通过原有 `opentodo_complete_tasks` 完成任务，必须给出 `completion_evidence`。工作台按实际调用入口记录操作者，不接受模型自行填写 actor。

| 操作来源 | 展示和记录 |
| --- | --- |
| Agent 自主判断 | AI 判定完成，可核查；记录依据和执行回合 |
| 用户当前对话明确确认，Agent 代记 | Agent 代记你的确认；保留 `user_confirmation_quote`、原消息 ID／时间和执行者 Agent |
| 用户在工作台勾选或核查确认 | 你已确认完成；保留直接操作时间 |
| 未经过新记录机制的完成 | 来源未记录，不回填猜测 |

引用必须与当前执行回合对应的真实用户消息匹配，后台不替模型判断语句含义。因此“代记”始终与用户直接点击分开，原话可核查。Agent 自主推断不能重新打开已有人工确认的任务；用户本轮明确要求更正时需引用原话。

待办页提供「核查 AI 完成」、来源标记、确认按钮和历史入口。历史列表可以查看当前状态、确认完成或改回未完成；更正追加记录，不抹掉原 AI 判断。生活时间线合并任务事件和生活观察，任务事件支持继续分页。

## 生活观察与 Agent 执行记录

- `cb_observe` 新增 `kind: life | execution`。生活活动、状态与事件使用 life；操作回执、浏览器步骤和技术检查使用 execution。证据类型 user／observed／inferred 继续单独保留。
- 生活时间线默认隐藏 execution，勾选「显示 Agent 执行记录」后可查看。两类分别取最近 200 条，执行记录不会占用生活观察的展示额度；任务完成、确认与更正记录保持原有展示。
- 新写入记录保留实际调用者与当前执行回合、托管事项 ID。托管作业中省略 kind 默认 execution；实际生活观察可显式写 life。用户手动记录默认 life。
- 旧记录没有 kind 时，来源明确含 `cb_browser` 或 `cb_maintenance` 且 evidence 非 user 的条目，按 execution 展示；其他旧记录保留 life。此规则只用于读取，不改写旧数据或猜测旧记录的操作者。
- 原文继续保存在本机，Agent 列表与统一检索仍可读取两类内容，并返回分类。异常与人工接手提醒沿用既有通道。
- 本批只读源码与差异，未运行测试、构建或浏览器验收，未重启工作台。

## 周期与可靠性边界

- OpenTodo 的完成回执区分 `completed` 与 `occurrence_completed`，后者携带 `occurrence_id`／`next_due`。记录当前期日期、实例 ID 和后续日期，核查针对完成实例，不再次完成已经推进的系列。确认按钮只追加确认记录，不再调用完成接口。
- 重新打开历史实例保留系列当前日期，不自动回滚后续周期。系列历史包含它的实例确认和更正。
- 完成／重新打开／创建请求在本工作台内串行；派发前保存意图，收到回执后先保存回执，再记录各项结果。断线、崩溃或读取失败不写成确定完成，不自动重放。收到成功回执但后续读取失败时，仍保留成功操作事件，卡片来源在缺少准确完成时间时显示未知。
- 人工确认检查页面所见事件 ID 与完成时间；状态变化后要求刷新。已有完成项再次由 Agent 转记用户确认时追加确认事件；普通重复完成回执不覆写原来源。
- 当前只追踪经过 CyberBoss 工具与按钮的变更。OpenTodo 原生完整看板仍保留全部任务；直接在那里操作有其原生历史，但不会被本地时间线猜作用户或 AI 操作。已知完成时间变化时不沿用旧来源。新机制没有迁移或修改旧完成数据。
- 用户与本地 Agent 共享文件系统，来源记录用于追溯正常工具操作，不宣称能防止任意本机程序篡改数据。

## 数据与实现

`data/desktop/desktop.json`（或已配置数据目录）的 `taskEvents` 追加保存请求、回执、完成、重新打开、确认、托管事项手动／工具状态变更与本次已处理记录，不随源码推送。关联具体消息的摘录也属于本机隐私数据。

- `src/desktop/task-history.js`：来源、完成状态装饰、串行变更、人工确认、历史分页。
- `src/desktop/observations.js`：观察分类、旧记录显示兼容、两类独立展示额度。
- `src/desktop/tools.js`、`server.js`：Agent 工具与浏览器入口归因。
- `src/desktop/jobs.js`、`app.js`、`notifications.js`：关联待办显示设置、销账来源和异常提醒。
- `web/src/Tasks.jsx`、`TaskHistory.jsx`、`Records.jsx`：卡片标记、核查与时间线。
- `templates/desktop-instructions.md`：创建循环工作、判断完成和尊重人工确认的规则。
