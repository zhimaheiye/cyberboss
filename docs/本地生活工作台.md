# CyberBoss 本地生活工作台

新增独立的 `desktop` 入口：保留旧微信入口，电脑端不需要微信账户。实现状态见 [当前交接](handoff/CURRENT.md)，历史见 [开发记录](development-history.md)。

## 打开方式

- 双击仓库根目录 `run-desktop.bat`，或运行 `npm run desktop`。
- 工作台默认是 `http://127.0.0.1:4317`，OpenTodo 是 `http://127.0.0.1:4319`。
- 首次使用在网页点击「开启桌面提醒」，允许浏览器通知。Edge / Chrome 可以从地址栏安装 PWA。
- 桌面提醒默认启用。已经允许通知的浏览器在页面启动时自动恢复订阅，首次授权会在你操作页面时申请。被浏览器阻止时，顶部按钮会提示去网站权限里调整。推送服务连接失败时会标明仅在页面运行时接收。
- 浏览器可保持后台，但本地 Node 工作台进程也需要运行。退出启动窗口会停止本机后台任务；本轮没有注册开机启动项。
- Codex 使用当前 Windows 用户的本地登录与 MCP 配置。缺少 ChatGPT 订阅登录时，在「设置 → 打开 Codex 官方登录」完成官方登录；账户凭据不经过聊天。
- 桌面入口始终使用自己的 Codex app-server，不复用旧共享端口，也不沿用旧微信会话。模型在工作台设置中修改；供应方固定为官方 `openai`，账户类型必须是 `chatgpt`。
- 「设置 → 拉取模型」从本机 Codex 的 `model/list` 接口分页读取可选模型，选择后点击「保存设置」。支持沿用默认模型和手动填写模型 ID；拉取只读取列表，不创建对话或执行任务，也不会自动覆盖所选模型。失败原因显示在按钮下方，未登录时先完成官方登录再重试。

安装依赖：`npm install --ignore-scripts`。安装固定版本 OpenTodo：`npm run desktop:install`。安装器下载固定版本二进制并比对锁定摘要，不启动服务。

## 数据归属

默认在本仓库的 `data/desktop`，不再随旧入口的 `CYBERBOSS_STATE_DIR` 写入用户目录。可用 `CYBERBOSS_DESKTOP_DIR` 显式覆盖。网页设置显示实际路径，仓库的整个 `data/` 已加入 Git 忽略。

从旧版切换时，先在原启动窗口按 Ctrl+C，等待本机工作台和任务服务退出，再重新启动。新目录尚不存在时，首次启动会将旧 `CYBERBOSS_STATE_DIR/desktop`（默认 `%USERPROFILE%\.cyberboss\desktop`）完整复制到新目录，再使用新目录。复制通过临时目录完成，不覆盖已有新目录；旧目录保留为备份，不再用于运行。这不迁移 Codex 自身的登录配置和原始会话目录，也不改变浏览器自身的缓存位置。

| 数据 | 本机位置 / 管理方式 |
| --- | --- |
| 普通待办、周期待办、完成历史、完整看板与日历 | `opentodo/` 下的上游 SQLite 数据；通过 OpenTodo MCP 管理，不直接改数据库 |
| 托管定义、执行记录、聊天、主动消息、观察记录 | `desktop.json`，由工作台单进程写入、临时文件原子替换 |
| 聊天图片 | `chat-images/`，图片随当前消息交给 Codex，历史消息保留原图 |
| 唤醒队列 | `wake-queue.json`，复用原项目 `SystemMessageQueueStore` |
| 记忆 | `memory/*.md`，可以自己编辑；工作台与 Agent 共用同一份文件 |
| 本地服务凭据 | `endpoint.json`、`desktop.json`、`opentodo-credentials.json`；只在本机，不提交 Git |
| Codex 原始会话 | Codex 本身的用户状态目录；工作台只保存会话引用和可见消息 |

备份时先关闭工作台，再完整复制上述数据目录，包含 OpenTodo 数据及凭据。当前没有跨设备同步和自动备份服务。

## 人与 Agent 共用任务

对话支持「添加图片」和在输入框里粘贴截图，发送前可移除附件。可以只发图片，也可以附上文字。每条消息最多 4 张 PNG、JPEG 或 WebP，单张最多 8 MB，合计最多 20 MB。

「待办事项」支持新增、编辑、按日期分组、完成／重新打开、转到对话。更完整的周期规则、看板与日历直接使用上游界面，从「完整看板与日历」打开；不是重新实现一套任务引擎。

保留计划日期但清除具体时刻的操作，目前从上游完整界面处理；简化编辑器不会把空时间发送为无效值。

Agent 调用 `opentodo_*` 工具访问相同的任务；任务变更会刷新工作台视图。完成周期待办调用上游 `complete_tasks`，本次完成记录和下一次日期由 OpenTodo 维护。

第一版记忆使用 Markdown 和关键词搜索，没有向量模型设置或 Basic Memory 运行依赖。向量检索留作后续优化；不要把文件落地等同于已接入语义召回。

## 托管事项

`cb_jobs` 与页面使用同一组定义：

| 类型 | 到时行为 |
| --- | --- |
| 到点提醒 | 直接写入通知收件箱，不依赖模型是否可用或额度是否足够 |
| 信息监控 | 唤醒 Codex 检索、核对来源、更新任务，再决定是否提醒 |
| 后台作业 | 按明确执行说明和已授权范围调用工具，保留执行记录 |
| 机会式事项 | 默认手动或事件触发；也可以由自然唤醒结合上下文判断 |

支持一次性、RRULE 周期（复用 `rrule`）、每 N 天、月末倒数日期、手动执行与本地事件入口。事件入口是 `POST /api/events`，请求体 `{jobId, data}`，需要本机 `endpoint.json` 中的 Bearer token。它提供被外部事件调用的接口，不表示已经安装任何设备 watcher。

编辑托管事项可直接选择「每小时整点」和「每隔若干小时」。整点规则为 `FREQ=HOURLY;BYMINUTE=0;BYSECOND=0`，时区采用事项设置。间隔小时规则按选定起点计算。小时级任务由 CyberBoss 调度，可关联 OpenTodo 普通待办卡片，OpenTodo 的待办 recurrence 不接收 `every hour`。这些规则同样适用于提醒、监控和自动操作，自动操作是否发送消息由执行结果决定。

## React / assistant-ui 工作台（2026-11-13）

前端已整体迁移到 React，源码在 `web/src/`，旧的 `web/app.js` DOM 拼接实现已移除。今天、对话、待办、托管事项、记忆、时间线和设置使用同一套导航、卡片、表单、弹窗、状态及响应式样式，图标使用 Lucide。

- 对话使用 [assistant-ui ExternalStoreRuntime](https://www.assistant-ui.com/docs/runtimes/custom/external-store) 接入原有 HTTP/SSE；消息仍由 CyberBoss 后端持久化，不创建第二套聊天存储。
- 使用 Thread、Message、Composer、Attachment、ActionBar 原语及 `@assistant-ui/react-markdown`。输入框自动增高，支持截图粘贴、拖入图片、附件移除、Markdown、复制消息、回到最新消息。未发送时显示发送按钮，有实际排队／执行才显示停止按钮。发送中、等待执行、思考和工具步骤分别显示。
- 请求失败时通过 `MessageNotSentError` 保留草稿；相同请求使用稳定 ID，服务端去重，避免网络断开后重试产生重复回合。不自动重放已经执行过的失败任务。
- 保留 Codex 审批、主动消息箱、历史通知定位、断线重连。审批卡片只承接现有后端支持的请求类型；没有添加后端不支持的分支编辑、重新生成或任意 MCP 表单能力。
- 待办支持看板／列表，完整日历继续使用 OpenTodo。托管事项包含小时循环、静默窗口、具体值核销、导入来源与执行记录。记忆编辑仍带原文并发检查。
- 启动 `desktop` 时 esbuild 在内存中编译本地前端并由同一个 HTTP 服务提供；无需另开开发服务器，不生成提交进仓库的大型产物。依赖安装后仍使用原来的 `run-desktop.bat`。修改源码后需重启工作台。
- 不再使用旧的 Marked / DOMPurify 前端依赖；Markdown 默认不执行原始 HTML，外部图片不自动加载。

## Kimi 浏览器维护与持续授权

集成按 Kimi CLI 的实际 `status` 判断守护进程、扩展和技能版本。更新由官方 `upgrade` 管理，文档不代表当前设备版本或连接状态。

本机维护授权单独写在当前数据目录的 `maintenance-policy.json`（被 Git 忽略）。没有此文件的新安装默认关闭自动维护；设置页可以启用或关闭。

- `cb_maintenance {action:"policy"}`：读取当前授权、状态和记录。
- `cb_maintenance {action:"check"}`：检查状态；授权开启时处理官方返回的更新和技能版本不匹配。
- `cb_maintenance {action:"prepare_browser"}`：保留健康连接；未连接时有限等待、检查宿主浏览器，按本机授权启动／恢复及同步版本。
- `cb_maintenance {action:"status"}`：只读实时连接。`diagnose`：只读连接日志、状态和浏览器安装线索。
- Agent 在已有对话或自然唤醒中自行判断是否需要调用，不为维护额外创建付费唤醒任务。每个浏览器工作流准备一次，不逐次点击重启。不再询问已经授权过的升级或重启时机。
- 维护调用串行化、设置执行超时，仅执行固定 Kimi 子命令，不执行状态返回的任意 shell 文本。失败、中断和实际步骤写入 `desktop.json` 的维护记录。失败不循环重试，扩展未连接不报告浏览器已就绪。
- 设置页提供状态、维护历史和手动维护入口；Agent 正在执行时禁用手动入口，避免与它的浏览器操作冲突。授权不包含更换端口、卸载、其它软件升级或账号变更。

默认自然唤醒间隔 30 分钟，可在设置改为至少 10 分钟。重启只合并补一次到期检查，不重演关机期间所有周期。同一作业已在执行或排队时，不重复排队。显式聊天优先于后台队列。

执行失败或进程中断后，相关作业变为需要核对的 `blocked`，不自动重放可能已经产生副作用的动作。一次运行上限 15 分钟；Codex 请求有超时，工作台可停止当前执行。需要权限或补充输入时显示在对话页，未获得回答不会擅自批准。

## 核销与通知语义

- 用户完成具体待办：调用上游任务完成工具。
- 已领一个兑换码：给监控项添加 `acknowledgedValues`，监控继续。
- 本月／本期已经处理：设置 `suppressUntil` 为下一期起点，不把长期事项标成 `done`。
- 生命周期结束：才将托管事项设为 `done`。
- 暂停、阻塞、过期有效窗口及本期静默均会阻止后台运行；核销同时取消该事项尚未投递的消息。

后台回合必须以 `silent` 或 `send_message` JSON 结束。工具执行完成与主动消息是两个独立事件；只有明确的 `send_message` 或到点提醒进入推送。后台协议异常只记录失败，不把原始输出误发给用户。

主动消息有单事项冷却和免打扰；默认 23:30～08:00 暂缓主动推送，到点硬提醒不受影响。浏览器 Web Push 由 `web-push` 库处理；网页保持打开时，SSE 同步也能把消息交给同一 Service Worker，两种路径按消息 ID 去重。

`accepted` 仅表示推送服务接收，不代表 Windows 已显示或用户已看到。消息始终保存在本地收件箱；点击通知打开对应消息，可在同一页面继续聊天。推送失败有限重试，失效订阅会移除。网络代理可使用进程环境的 `HTTPS_PROXY` / `HTTP_PROXY`。

## personal-hub 接管边界

导入支持个人任务仓库的 `automations/jobs.yaml`、`reminders/reminders.yaml`，保留“长期定义 + 每次执行记录”的区分。

「交给 Agent → 从 personal-hub 导入定义」读取两个 YAML：

- 活跃源事项先导入为 `draft`，不是迁入即启用。
- `paused` / `blocked` / `done` 原样保留；已处理兑换码、静默窗口、有效期限、来源路径、完整原始定义一起保留。
- 按 `personal-hub:{reminders|jobs}:{id}` 去重；重复导入跳过已有项，不覆盖工作台的新状态。
- 源文件、源平台及其运行实例不修改。正式启用前需要确认旧平台负责人、当前设备工具与执行权限，避免双重运行。
- 来源存在历史日期与语义冲突，例如兑换码条目的周频规则和“每天检查”说明；导入保留原规则，接管时需要在工作台校正，不能无声猜测。

导入仅建立候选事项，不直接启动来源平台的现役作业。

## 实现与验证边界

### 浏览器自主恢复（2026-11-14）

既有故障显示扩展可能晚于旧程序的 5 秒等待窗口才连上。旧 Agent 没有复查实时连接，使用过期状态要求用户启用扩展。断连状态不能证明扩展被禁用；公开记录不包含个人原始日志。

`cb_maintenance status` 读取实时状态；`diagnose` 只读状态、连接日志及 Windows Edge/Chrome 常规配置中的扩展安装线索，不保存浏览器凭据。`prepare_browser` 保留健康连接，在断连时等待最多 30 秒，再检查宿主浏览器；如果唯一匹配的原配置对应浏览器尚未运行，可以启动该配置。按授权有限启动／重启及同步版本后再次等待；未恢复时返回 `needs_diagnosis`，不把它标成必须人工处理。非标准浏览器或多个配置由 Agent 根据本机证据继续排查，不猜选账号。

`cb_browser` 每次派发前读实时状态，必要时先恢复；派发后的动作绝不自动重放。进行中的浏览器请求会阻止维护程序重启守护进程。暂时离线且没有业务副作用的循环任务保留调度；未知点击结果、真实身份验证等门槛另行核对。

Agent 通过 `cb_jobs save` 阻塞任务必须提供 `blocker`：类别、具体现场证据、已尝试的恢复动作和下一步。连接类人工阻塞还会再次查实时连接，并要求近期诊断记录。用户直接在界面修改状态仍可用。这是执行流程约束，不是对拥有本机 shell 权限的 Agent 的安全隔离，也不能机械证明模型所写证据真实。原有任务的业务权限不变，新增提示词明确站点动作与基础设施恢复的不同边界。

该改动仅依据代码、既有记录与实时连接排查；未重跑业务动作或执行测试、类型检查、lint、构建、浏览器交互验证。新机制需重新启动工作台加载。

### 循环任务技能与执行进度（2026-11-13 后续改进）

既有长任务记录显示，多次通过 apply_patch 写临时请求文件带来额外模型回合，而浏览器请求本身较快。因此将文件体传输封装为一次工具调用。此结论来自历史记录分析，尚未做性能测试；公开文档不包含真实业务内容与操作流水。

新增的 `cb_browser` 将 UTF-8 独立请求文件写入、发送到已确认端口的 Kimi `/command`、清理文件封装为一次调用。它沿用 Kimi session 和操作规范，不自动重试可能产生副作用的请求，也不增加任务权限。临时文件留在本项目数据目录；正常请求返回后删除。Agent 不再需要为每一个浏览器动作反复调用文件修改工具和 curl。

执行记录现在采集工具开始／结束、具体输入、输出、错误、退出码、单步及总耗时；区分等待模型、等待工具、等待批准和正在输出。仅记录推理活动发生的时间，不保存私有推理内容。显示超过一分钟没有新事件的提示，但不把无事件直接判成卡死。返回体包含 `ok:false` 等明确失败时，不再仅因外层命令退出码为零而显示成功。

`/api/state` 提供轻量进度，展开详情时读取 `/api/run?id=...`。旧版只有名称的记录会尝试从该线程的本机 Codex 会话按执行时间窗只读还原工具调用和公开输出，排除用户提示、私有推理及其它回合；不会覆盖工作台数据。原始日志缺失或超过读取上限时如实显示旧记录限制。参数和输出限长并遮盖常见凭据字段。

`cb_skills` 提供 list/read/save。每个事项的经验落在 `data/desktop/skills/task-事项ID/`：

- `vN.md` 保存版本草稿与来源，`SKILL.md` 保存已启用版本，元数据保存在 `desktop.json`。
- 保存时必须指向该事项的真实执行记录，提供操作步骤、成功判断、失败处理及实际观察，并带当前版本号防止覆盖。
- 草稿只有在来源回合正常结束、Agent 明确报告 `learningOutcome:verified`、任务仍启用且定义未变化时才能启用。`silent`、退出码为零或无报错不单独证明可复用。核验来源是 Agent 的工具观察，不冒充人工确认。
