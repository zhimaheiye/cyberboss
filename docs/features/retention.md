# 正常巡检记录保留策略

## 已确定行为

用户选择正常巡检保留最近 **7 天**。由工作台进程执行定期清理，开发过程中不直接删除运行数据。

- 默认启用；设置页可调整 1～365 天或关闭。
- 复用工作台的后台循环，每 24 小时检查一次；首次启动或安排检查后在空闲时执行。电脑与工作台未运行时不执行。
- Agent 执行中、队列有待执行事项、向量索引更新中均延后检查，结束后由循环继续判断。
- 不额外唤醒付费模型。Agent 可调用 `cb_retention status/preview/request` 读取策略、查看候选数量、安排检查；不能通过此工具覆盖保留期或指定任意数据删除。
- `request` 是安排请求，实际结果见设置页的检查时间与清理统计。

## 清理条件与保留内容

候选为超过保留期、后台正常完成且最终 `silent` 的周期 `watch`／`operation` 或自然唤醒记录。失败、中断、取消、显式 uncertain、错误／说明未解决、技能保存出错、工具步骤失败或未完成、步骤被截断均不进入候选；当前托管事项阻塞或带错误时也保留。

每项最新一轮保留。对话、通知、任务状态历史、技能任一版本、关联与关联历史引用的执行记录保留；生活观察、用户记录、近期操作记录所引用的执行也保留。关联保护包括用户已经忽略的关联，保留其核查依据。

符合条件时，删除该执行记录及已关联的过期操作观察、对应 `run:`／`event:` 向量。旧版操作观察缺少 runId 时，只在其写入时间唯一落入一个后台执行区间时关联；无法确定归属的记录保留。

任务定义、完成与更正历史、用户对话和提醒、生活观察、笔记、工具、技能、句库与收藏不在清理范围。Codex 自身的原始会话文件不由此功能删除。无引用保护的过期正常执行原文会从工作台删除，不另外留一份完整流水副本。

## 统计与可靠性

- 保留累计数量和最近 30 批简短统计，包含按事项汇总的执行数量与时间范围，不保留整批已删除的原文。
- 预览只返回数量；执行时重新生成候选，使用当前策略和引用关系。
- 向量先删除，再保存原记录的变化。保存失败时恢复内存中的原记录；已经移除的派生向量可由索引功能重新生成。两份文件不宣称跨文件事务。
- 清理与索引更新互斥，防止进行中的旧索引快照重新写回已清理内容。
- 错误显示在设置页，下一次日检查或用户／Agent 重新安排后重试，不进入紧密循环。
- 向量设置页显示已保存片段的来源分布，方便区分任务、执行摘要、句库等内容。

## Codex 会话命名与自动归档（2026-11-18）

- 工作台会话分别命名为 `CyberBoss · 主对话`、`CyberBoss · 自然唤醒`、`CyberBoss · 任务名称`。新会话在首轮结束后命名，已有会话在后台日检查中补齐；任务改名后同步名称。
- 只登记本机工作台保存的 `sessionThreads`、旧版 `threadId` 与执行记录中的会话编号。不会凭标题相似或同属一个目录管理其它 Codex 对话；已丢失编号的旧会话不自动接管。
- 独立于巡检流水保留开关，每 24 小时在工作台和队列空闲时检查一次，无须调用生成模型。已替换、所属任务已删除或明确标记 `done` 的会话，距离工作台记录与 Codex 元数据中较新的活动时间至少 7 天后归档。
- 当前主对话、自然唤醒，以及仍需复用的任务会话保留。暂停、阻塞、草稿或暂时超出执行时间窗口都不视为任务结束。归档检查期间执行队列等待，新的用户请求使维护在当前 RPC 完成后让出执行。
- 使用 Codex 的归档接口保留会话原文，不直接删除文件。工作台读取执行详情时同时查找 `sessions` 与 `archived_sessions`。已完成任务若被用户重新启用，执行前恢复对应已归档会话，再继续复用。
- 每次实际归档后立即保存状态；若进程在归档成功与保存之间退出，下次通过原始会话路径核对。接口失败记录具体原因，下一次日检查重试；单个会话失败不阻止其它会话。
- 设置页「巡检记录保留」下显示会话整理数量、检查时间、最近 30 批统计与错误。登记、命名和归档状态保存在本机 `desktop.json` 的 `threadMaintenance`，属于运行数据。

实现：`src/desktop/thread-maintenance.js`，接入 `app.js` 的后台循环、执行队列和退出流程；`agent.js` 登记与命名，`run-history.js` 保留归档后的详情读取，`RetentionSettings.jsx` 展示维护状态。
